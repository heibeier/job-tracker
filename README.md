# 求职投递记录管理器

一个本地桌面应用，用来记录投递过的公司 / 岗位 / JD，管理投递状态和后续跟进。
**数据全部存在本地，不上传任何服务器。**

## 功能

- **两种视图**：列表（一屏看全、可就地改状态）、看板（管道式分列、卡片拖拽改状态）
- **三栏可拖拽伸缩**：左栏 / 列表 / 右详情栏之间的分隔条可以左右拖动调宽，双击恢复默认
  （左栏 150–380px、详情栏 300–760px），也可用方向键微调；拖出来的宽度会记住，
  下次打开还是你设定的尺寸。窗口不够宽时两侧会自动让位，保证中间列表至少 360px
- **四种录入方式**：手动填写 / 粘贴 JD 文本 / 上传 JD 截图 / **Ctrl+V 直接粘贴截图**
- **⚡ Ctrl+V 快捷建档**：复制一张 JD 截图 → 在应用里任意位置按 `Ctrl+V`
  → 自动落盘 → 交给本地模型解析 → 打开新建表单（字段已预填、截图已附上）。
  弹窗打开时不接管粘贴；文本框里的正常文字粘贴不受影响。
- **AI 自动解析**：点一下「✨ AI 解析」，本地模型把 JD 解析成结构化字段并自动填表
  （公司、岗位、城市、薪资、经验/学历要求、岗位职责、任职要求、技能关键词、福利亮点）
- **状态时间线**：每次改状态自动留痕，可回溯整条投递进度
- **跟进提醒**：每进入一个阶段就按该阶段的固定间隔算出一个具体跟进日期，
  到期后左栏顶部出现「⏰ 该跟进了」入口、列表/看板对应行加橙色标记，
  详情页一键「已完成跟进」顺延一个周期（规则见下方专节）
- **筛选与搜索**：按状态、投递渠道筛选；支持公司/岗位/技能/备注全文搜索
- **导入导出**：JSON（含全部字段，可迁移）、CSV（带 BOM，Excel 打开不乱码）
- **JD 截图自包含**：选中的截图会复制进数据目录，原图删了也不影响

## 跟进提醒怎么算的

**建档时会先问你真实投递日期**（表单第一个分区，带「今天 / 昨天 / 前天」快捷按钮），
因为「今天新建」和「今天投的」经常不是一回事。这个日期就是第一段计时的起点。

之后**每进入一个阶段，就按该阶段的间隔算出一个具体日期**写进记录的「跟进日期」字段
——它是个看得见、能手动改的日子，不是藏在代码里的规则：

| 阶段 | 默认间隔 | 阶段 | 默认间隔 |
|---|---|---|---|
| 已投递 | 7 天 | 二面 | 7 天 |
| 已查看 | 7 天 | 三面 | 7 天 |
| 笔试 | 14 天 | HR面 | 5 天 |
| 一面 | 7 天 | Offer / 已拒 / 已挂 / 已放弃 | 不提醒 |

几条配套规则：

- **改状态就重算**，从改的当天起算。所以「刚面完在等结果」和「投出去一直没动静」
  用的是同一套规则，不用分别配置。
- **手动改过的日期优先**：在表单里自己填了跟进日期，下次改状态之前都按你填的来。
  填 0 天（或改到终态）就等于这条不提醒。
- **终态自动清空**：改成 Offer / 已拒 / 已挂 / 已放弃 时跟进日期会被清掉，不会再提醒。
- **补录旧记录不会算错**：把「投递日期」填成一周前，跟进日期会跟着那一天算，
  建档后立刻就是「该跟进」状态，而不是被当成今天刚投的。
- 间隔都能在「设置 → 跟进提醒」里改，每项右边有 ↺ 恢复默认。
- 到期的记录**只做应用内标记，不弹系统通知**。

> 本功能上线前建的记录，启动时会按上面的规则补算一次跟进日期。
> 补算只填空值，不会覆盖你手动设过的日期。如果某条你确实不想被提醒，
> 把它改成终态阶段即可（手动清空的话，下次启动会被重新补上）。

## 配置本地模型

打开应用 → 右上角「**设置**」：

| 项 | 说明 |
|---|---|
| 服务地址 | Ollama 地址，默认 `http://127.0.0.1:11434` |
| 模型名称 | 默认 `qwen3-vl:4b`；点「测试连接」会列出本机所有模型，点一下即可切换 |
| 单次生成 token 上限 | **建议保持 2000 以上**（原因见下方「已知坑」） |

> 没有 Ollama？去 https://ollama.com/download 装好后执行 `ollama pull qwen3-vl:4b`。
> 有视觉能力的模型（如 qwen3-vl 系列）才能解析 JD 截图。

## ⚠️ 已知坑与设计取舍

**1. 为什么要强调 token 上限？**
`qwen3-vl:4b` 这类模型带「思考模式」，且 `think: false` 参数关不掉它。思考内容会写进
单独的 `thinking` 字段——**如果 token 预算给少了，思考会把预算吃光，`content` 返回空字符串**。

应用对此做了三层防护：
- 默认 `numPredict = 2400`
- 拿到空内容 / 非法 JSON 时**自动把预算翻倍重试**（最多 3 次）
- `content` 为空时，会尝试从 `thinking` 字段里再抠一次 JSON

**2. 为什么用 JSON 文件而不是 SQLite？**
`better-sqlite3` 这类原生模块需要 node-gyp / Visual Studio 构建工具，在普通用户机器上
安装和打包都可能失败。个人投递记录规模（数百条）用 JSON 完全够，且写入采用
「先写临时文件再 rename」的原子方式，中途崩溃不会损坏数据。

**3. 模型能力边界**
本地 4B 模型擅长**模式化任务**（抽取字段、摘要、格式规范化），不擅长需要判断的复杂推理。
如果解析结果不理想：
- 换更大的模型（设置里点「测试连接」后切换，如 `qwen3-vl:8b`）
- 或把 JD 文本直接粘进去（纯文本比截图解析准确率更高）

**4. 关于国内网络**
`npm install` 时 Electron 二进制从 GitHub 下载容易超时，项目内 `.npmrc` 已把
Electron 镜像指向 npmmirror，并把 npm 缓存放进项目目录。若仍失败，检查网络/代理。

## 项目结构

```
job-tracker/
├── electron/            主进程（Node 侧，编译成 CommonJS）
│   ├── main.ts          窗口创建 + 中文应用菜单 + 所有 IPC 接口
│   ├── preload.ts       contextBridge 桥接（渲染层只能调明确暴露的方法）
│   ├── store.ts         JSON 存储、增删改查、导入导出、图片归档
│   └── ai.ts            Ollama 调用 + JD 解析提示词 + 空回复重试
├── shared/types.ts      主进程与渲染层共享的类型定义
├── shared/followup.ts   跟进提醒的规则表与日期计算（两侧共用，保证算法只有一份）
├── src/                 渲染层（React + TypeScript）
│   ├── App.tsx          应用外壳：状态、筛选、视图切换
│   ├── views/           ListView（列表）、KanbanView（看板拖拽）
│   ├── components/      DetailPanel（详情）、ApplicationForm（表单）、SettingsDialog（设置）、Resizer（左右面板拖拽调宽）
│   └── styles.css       全部样式
├── docs/
│   └── JD解析提示词.md   软件内置的 JD 解析提示词（与 ai.ts 中一致）
├── index.html
├── vite.config.ts       渲染层构建（base: './' 以便 file:// 加载）
├── tsconfig.json        渲染层 TS 配置
├── tsconfig.electron.json  主进程 TS 配置
├── .npmrc               镜像与缓存配置（国内网络下 Electron 下载加速）
└── README.md            本文件
```
